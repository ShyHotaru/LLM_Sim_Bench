Feel the speed

Time to first token follows the prefill speed for the prompt; every later token follows the decode speed at the current context fill. The text is filler.

How the estimate works

  • Memory: weights (parameters × bits per weight) plus KV cache for the full context. Whole layers go to GPUs first, the rest to system RAM. On Apple Silicon the GPU may use about 75 % of unified memory.
  • Decode is memory-bandwidth bound: each token reads every active weight and the filled KV cache, plus a fixed per-layer overhead.
  • Prefill is compute bound: about 2 FLOPs per active parameter per prompt token.
  • Calibration: efficiency factors are fitted to public llama.cpp benchmarks.

Estimates for a single request with llama.cpp-style offloading. Larger models, long contexts and CPU offload are extrapolations; treat results as planning guidance, not guarantees.
